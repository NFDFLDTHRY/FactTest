# Public-HTTPS probe of a generated bundle (D25 deployable probe)

STATUS: the execution environment that produced evidence/D25 cannot reach a public HTTPS origin able to host the
generated WebApp (tests/physical/public-https-probe.sh: the githack and GitHub Pages hosts are refused by the egress
policy at CONNECT; raw.githubusercontent.com is reachable but serves every file as text/plain with
`x-content-type-options: nosniff` and a sandboxing CSP, so module scripts are refused).  Localhost is NOT substituted:
the public-HTTPS claim is [UNK] (FACT-D25-PUBLIC-HTTPS) until the run below supplies external evidence.

## What to deploy

Any bundle directory generated by the current compiler, e.g. `evidence/D25/bundles/byte-relay/compile/bundle/`
(bundle_id and artifact sha256s in its `bundle.json`; the same bundle is published byte-identically on this branch at
`evidence/D24/physical/compile/bundle/`).  Copy the directory as-is to a static HTTPS host that serves:

| file                 | content-type                    |
|----------------------|---------------------------------|
| index.html           | text/html                       |
| *.js                 | text/javascript                 |
| *.wasm               | application/wasm                |
| manifest.webmanifest | application/manifest+json       |
| bundle.json          | application/json                |

The host must not add a Content-Security-Policy that blocks same-origin module scripts, and must not rewrite bytes
(the runtime compares every fetched file with the sha256 recorded in bundle.json).  GitHub Pages, Netlify, Cloudflare
Pages or any object store behind HTTPS satisfy this; a tunnel to 127.0.0.1 does not count (it proves the tunnel, not a
public origin).

## Exact user-run command

From a checkout of this repository, with Playwright's Chromium installed (`/opt/pw-browsers` here, or
`npx playwright install chromium`):

```sh
node host/harness/webapp-probe.mjs --url https://<host>/<path>/index.html \
  --payloads fixtures/commissioning/payloads.json \
  --loss WEBGPU --expect-e0 WEBGPU --expect-e1 CPU_WASM64 \
  --out evidence/D25-public/<host>/webgpu
node host/harness/webapp-probe.mjs --url https://<host>/<path>/index.html \
  --payloads fixtures/commissioning/payloads.json --no-webgpu --loss none --expect-e0 CPU_WASM64 \
  --out evidence/D25-public/<host>/no-webgpu
```

For another specimen replace the payload file and the expectations by the `expect` block of its
`fixtures/genericity/<name>/specimen.json` (`webgpu.e0/loss/e1`, `no_webgpu.e0`).  On a machine with a hardware GPU the
`--enable-unsafe-webgpu` launch flags in the harness still apply; the identity record shows which adapter answered.

## Expected evidence (schema of `probe-record.json`)

```text
harness              "host/harness/webapp-probe.mjs"
mode                 "external-url"                      (never "served-loopback" for this claim)
url                  the public https:// URL driven
identity.browser     product, revision, js_engine, user_agent, executable, launch_options
identity.host        platform, release, arch, uname, hostname, cpus, node
identity.page        origin (https://...), secure_context true, cross_origin_isolated, shared_array_buffer,
                     webgpu_exposed, adapter {vendor, architecture, device, description, is_fallback_adapter,
                     features[], limits{}}
identity.http_status 200; identity.response_headers (content-type of index.html, any CSP)
identity.artifacts   bundle_id, strategy_data_sha256, fetched_sha256 {file: sha256} == recorded_in_manifest,
                     every_fetched_file_as_recorded true
identity.toolchain   the proof-set pins of the checkout the harness ran from
steps                E0-init (admissions, activation), E0-transfer (per relation x payload: status EXECUTED, exact_runtime
                     true, exact_harness true), controlled-loss (admission REJECTED, one observation delta with the
                     stale plan), E1-transfer, service-worker (registrations, cache keys)
verdict              e0_all_exact, loss_witnessed, e1_all_exact, stale_plan_invalidated, artifacts_as_recorded,
                     only_bundle_files_requested, no_runtime_codegen, service_worker_registered,
                     cache_storage_populated, expectations_met - all true; exit code 0
evidence-tape.ascii  opens with @{bundle strategy_data="<sha256>" ...} equal to bundle.json strategy_data_sha256
```

Bind the result with `factc observe --tape <out>/evidence-tape.ascii --system byte_relay --source
fixtures/commissioning/byte-relay.ascii --bundle-manifest <bundle>/bundle.json --evidence-class PHYSICAL_BROWSER`
(`evidence_lineage OBS` proves the tape belongs to the deployed bundle).  Commit the `evidence/D25-public/` directory
through the Factory as its own delta; the fact FACT-D25-PUBLIC-HTTPS moves from [UNK] to [RUN] only with that
evidence, with the origin recorded in its ENVIRONMENT node.
